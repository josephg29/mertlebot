# Mertle — Portfolio Notes

> One-page summary for reviewers. For setup and API details, see the [README](README.md).

## The one-sentence version

Mertle turns a plain-English electronics idea into a buildable project — parts, Arduino code, a custom-rendered wiring diagram, and a Wokwi simulation — and it's engineered around the assumption that the language model will sometimes get the wiring wrong.

## Why it's harder than it looks

Anyone can ask an LLM to "write Arduino code for a temperature sensor." The hard part is the **circuit**: an LLM will confidently produce a diagram where a wire lands two pixels off the SDA pin, or where the code says `#define DHT_PIN 7` but the diagram wires the sensor to pin 4. Those mistakes are invisible in prose and fatal on a breadboard.

Mertle's answer is a **deterministic verification layer** that sits between the model and the user:

1. **Parse** the model's diagram out of the generated guide.
2. **Validate** it geometrically against real board pin coordinates — every component pin must connect to a real board pin within a 10px tolerance, I2C lines must use the dedicated SDA/SCL pins for that specific board, wire labels must match where they physically land.
3. **Cross-check** the generated code's pin constants against the diagram.
4. **Repair** near-miss diagrams by snapping wires back onto their pins — no extra model call.
5. **Escalate** to a stronger model (Sonnet) only when local repair isn't enough.

This is the part I'm proud of: it's real systems work — geometry, parsing, a repair algorithm — wrapped around the model, not just a prompt.

## What I built from scratch

- **A custom SVG wiring engine** (`src/lib/wiregen/`). Board and component geometry is defined pin-by-pin; a de-overlap pass routes wires so they don't stack; the canvas pans and zooms. No Fritzing, no embedded third-party renderer. The image in the README is this engine's real output.
- **The validation + repair pipeline** (`src/lib/projectSupport.js`), ~700 lines of pure, testable logic.
- **A two-tier model pipeline** that keeps latency and API cost down by validating a fast draft locally and only escalating when needed.

## Engineering practices on display

- **Tests where they matter** — the validation engine is unit-tested with fixtures built from the real pin geometry, so the tests exercise the actual tolerance math, not mocks.
- **Honest scope** — the app is deliberately stateless (no accounts, no database). Dead code from an earlier accounts feature was removed rather than left to rot, which also made the deploy a single native-dependency-free Node image.
- **Reproducible imagery** — the screenshots are generated by committed scripts that mount the real components in a headless browser.

## Tech

SvelteKit 5 / Svelte 5 runes · Node · Anthropic Claude (`claude-sonnet-4-6` + `claude-haiku-4-5`) · Vitest · Docker / Fly.io.
